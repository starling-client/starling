# FML loader APIs and their Sunrise routes

NeoForge's mod loader (FML) hands a mod its own files and paths: the list of mod files, a config's full path, the
game directory, an update URL. This page lists the Sunrise counterparts and explains where their contracts differ.

A row marked **by design** is not a gap. A row that links an issue is a real gap that is tracked, not by design.

| FML API | Sunrise route | Why it differs |
| --- | --- | --- |
| [`ModList.getMods`](https://aldak0.ru/javadoc/26.3.x/net/neoforged/fml/ModList.html) | `mods()` on `RegistrationContext`, `DataLoadContext`, `LoopContext` or `WorldgenHost` lends `&LoadedMods`. Use `ids()`, `iter()` or `get(id)` (see [Load phases and access](../concepts/load-phases.md#load-contexts)). | The inventory is already in memory and lists packages in dispatch order. Use `LoadedMods::clone(cx.mods())` only if you need to keep the inventory beyond the context borrow. |
| [`ModList`](https://aldak0.ru/javadoc/26.3.x/net/neoforged/fml/ModList.html) file metadata: `getModFiles`, `getModFileById`, `forEachModFile`, `applyForEachModFile`, `applyForEachModFileAlphabetical` | Use `LoadedMods` for package information; for file bytes, see [Data files](../how-to/native-mods/03-data-files.md#another-packages-files). | **By design.** A package is one mod, so there is one `PackageInfo` per mod rather than a file with several mods in it. It carries the id, version, kind, side, namespaces, dependencies and the manifest's details (display name, description, authors, license, links, the icon's path inside the package and properties), and no path to the package on disk. It is local metadata, not a Wire record. There is no alphabetical variant; sort the IDs yourself if you need that order. |
| [`ModConfig.getFullPath`](https://aldak0.ru/javadoc/26.3.x/net/neoforged/fml/config/ModConfig.html) | `ConfigFile.file`, a name relative to `config/` (or to a world's `serverconfig/`), and `Host::config_files()` for the calling mod's own files (see [Config files and settings](../how-to/mod-settings.md)) | **By design.** `config_files()` is bound to the calling mod and never lists another mod's files. |
| [`FMLLoader.getGameDir`](https://aldak0.ru/javadoc/26.3.x/net/neoforged/fml/loading/FMLLoader.html) and [`FMLPaths.GAMEDIR`](https://aldak0.ru/javadoc/26.3.x/net/neoforged/fml/loading/FMLPaths.html) | `RegistrationContext::instance_dir()` during registration; `Host::instance_dir()` when a host is available (see [Load phases and access](../concepts/load-phases.md)) | Registration borrows the native path captured at startup, or returns `RegistrationReadError::Unavailable` if no snapshot is installed. |
| [`IModInfo.getUpdateURL`](https://aldak0.ru/javadoc/26.3.x/net/neoforged/neoforgespi/language/IModInfo.html) | None in a mod. The mod browser compares the installed version with the newest one in Sunrise's registry (see [Installing and using mods](../players/installing-mods.md)) | **By design for registry mods:** updates come from the registry, not from a URL a mod declares. A mod installed from outside the registry has no update check yet. |
| [`ModList.getModFileById`](https://aldak0.ru/javadoc/26.3.x/net/neoforged/fml/ModList.html)`(id).getFile().getContents()` / [`IModFile.getContents`](https://aldak0.ru/javadoc/26.3.x/net/neoforged/neoforgespi/locating/IModFile.html) (a `JarContents`: `readFile`, `containsFile`, `visitContent`) | `RegistrationContext::package_files(id)`: `list(folder)` and `read(path)` over an enabled package's `assets/` and `data/` files (see [Data files](../how-to/native-mods/03-data-files.md#another-packages-files)) | Only the content files are served, read through content loading's own reader and checks; the package's code and manifest are not. |

A mod that needs to know who else is loaded asks `LoadedMods`; one that needs a package's assets or data
reads them through `RegistrationContext::package_files` (see [Data files](../how-to/native-mods/03-data-files.md#another-packages-files)).
For config files, use the config-file service above. If none answers, file an issue naming the FML API and what
the mod does with it.
