# Q-002: may a pack's buffer block name a descriptor `set`?

- **Spec section:** revision 1, 6.5 (lines 973-975), `bufferObject.<index>`: "Bound as `layout(std430, binding =
  <index>) buffer`". The spec names no `set` for a pack's buffer blocks. Line 810: "Packs are GLSL written for OpenGL".
  Its language source `[GLSL]` (line 30) is the GLSL 4.60.8 specification, whose 4.4.5 says: "The set qualifier is
  only available when targeting Vulkan", and that it is a compile-time error to apply `set` "when not targeting an API
  that supports descriptor sets"; 4.4's table lists `set =` for `uniform` and `buffer` as "Vulkan only".
- **Question:** read together, these make a pack buffer block with a `set` in its layout invalid GLSL for the format's
  target. Is that the format's rule in every tier, so that such a block is refused, or do packs of some tier write
  `set` and expect it to be ignored (the block bound at its `binding` whatever set it names)?
- **What was observed:** sunrise-org/sunrise#5641. Before it, where Sunrise bound such a block depended on where the
  pack wrote its `set`: in set 4, where the game binds every pack buffer block, unless the `set` came after
  `binding`, which put the block in the set it named. None of the six packs checked for #5533 (Complementary
  Reimagined r5.9.3, BSL 10.1.8, Bliss 2.1.2, Photon 1.4, Solas 3.9, I Like Vanilla 1.5.0b) writes `set`. Sunrise
  follows GLSL 4.4.5 for now: a buffer block with a `set` in its layout refuses its program, with a load note at the
  `set`'s file and line naming the block, and the program is skipped as any program that fails to translate.
